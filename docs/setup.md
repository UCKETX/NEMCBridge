# 部署指南

## 前提

- 能运行已适配版本的 Bedrock Dedicated Server；当前实测为 1.21.124.2。
- FGAuth 验证服务器及属于自己的房主机器人令牌。令牌由所选服务提供，本项目不附带账号或令牌。
- NEMCBridge可连接验证服务器、网易房间节点和后端 UDP 端口；玩家侧需要可用的 WebRTC 网络连接。

FGAuth 默认地址是 `https://fgauth.ucket.top`，可在控制台改为其他兼容服务，不限制服务域名或 HTTPS 端口。程序会跟随验证站的 HTTPS 跨域跳转，支持 IPv4 / IPv6 分流。房主账号通过所选服务鉴权，令牌会发送到该服务，请使用自己信任的服务。

新版开房鉴权通过一次性挑战、X25519 临时密钥协商、Ed25519 服务端签名和 AES-256-GCM 加密。FGAuth 要求 NEMCBridge 使用安全协议 2，且版本不低于 **v0.1.9**；v0.1.9、v0.1.10、v1.2.0 及更高版本均通过版本检查，通过后仍须验证机器人令牌及网易账号。无需配置可信摘要清单或随每次发布同步摘要；已有清单不再参与开房检查。仍要求摘要匹配的旧版 FGAuth 需要替换为采用最低版本规则的新版并重启。

自行编译时应通过 `-ldflags "-X main.version=v1.2.0-local"` 注入实际构建版本。默认的 `dev` 无法进行最低版本比较，会收到更新提示。

开房成功后，程序加密回传房间号，供用户活动记录及管理员审计查询；重连产生的新房间号也会回传。回传失败会关闭刚创建的房间并重试。需要配套升级 FGAuth 和 NEMCBridge，不自动回退到旧明文校验。

首次通过 HTTPS 连接验证服时，程序在数据目录的 `auth-trust/` 中保存服务端公钥，后续公钥变化直接拒绝连接。升级和迁移请保留该目录；FGAuth 端需保留 `encryption.key` 才能保持身份不变。首次连接仍依赖 HTTPS 的可信性。公钥不匹配时，应先通过可信渠道核对服务端身份，再由管理员更新对应 `.pub` 文件。应用层加密防止普通改包、重放和伪造成功响应，不能防止专门逆向并修改本机客户端。

## 后端设置

### BDS

在 BDS 的 `server.properties` 中设置：

```properties
online-mode=false
compression-algorithm=zlib
block-network-ids-are-hashes=true
```

`zlib` 对应当前桥接支持的 Flate 压缩。房间版本字段和 BDS 版本是两个独立配置；已验证房间版本为 `1.21.120.0`，不要按后端版本随意替换。

国际版玩家直接连接 BDS；需要远程直连时自行配置 UDP 端口转发、防火墙和访问权限。后端关闭 Xbox 登录认证后，名称、UUID、XUID 不能作为已认证账号的凭证。NEMCBridge并不提供额外的玩家账号授权系统。

网易玩家原始登录中的 XUID 通常为空。桥接会优先使用网易账号 `netease_uid`，缺失时使用 `netease_uuid`，生成固定的数字兼容 ID 并放入后端 XUID 字段，便于服务器日志及插件区分玩家；已有的有效 XUID 会保留。兼容 ID 不是微软分配的 Xbox XUID，不适用于 Xbox 账号查询或正版验证。映射不使用玩家名称、临时会话或随机数，后端玩家 UUID 也按上述网易账号生成，以隔离不同账号的背包、位置等持久数据；如果两种网易账号字段都缺失，则保持 XUID 为空。

升级到按账号隔离 UUID 的版本后，网易玩家会使用独立存档；此前因占位 UUID 产生的共用玩家数据仍留在世界里，不自动迁移给任一账号。需要恢复旧物品时，请先备份世界再由管理员分配。

### Purpur / Paper + Geyser（实验性）

Geyser 必须支持当前网易桥接的基岩版协议 **860**。本次适配使用的方块表与 **Geyser 2.9.1-b999（dbed595）** 一致，其原版顺序方块 ID 会在收到 StartGame 时自动识别并双向转换，无需在桥接中增加开关。不要在 Java 的 `server.properties` 中添加 `block-network-ids-are-hashes`；该选项只对 BDS 有效。

桥接目标填写 Geyser 的基岩版 **UDP** 地址和端口，例如 `127.0.0.1:19132`，不能填写 Java TCP 端口。Geyser 需要允许无 Xbox 签名的代理登录，并配置相应的 Java 认证入口。若使用离线入口，则 Geyser 的 `remote.auth-type`（新版为 `java.auth-type`）设为 `offline`，单机 Java 后端 `online-mode=false`。这会关闭该 Java 后端的正版认证；保留 Java 正版入口需要独立配置代理与认证。Geyser UDP 离线入口应只允许可信桥接机器访问。

当前转换覆盖区块和子区块的方块调色板、单个及批量方块更新、物品栏与装备、配方和创造物品栏、方块实体元数据以及玩家物品交互。生物群系、NBT、区块索引及物品额外数据保持原始字节。顺序模式暂不支持自定义方块表或区块 blob 缓存；Geyser 的普通区块传输不使用该缓存，网易客户端仍可发送自己的缓存能力声明。

已通过协议与回归测试，并由用户确认真实网易客户端连接 Geyser 的进服测试通过；这不代表所有插件、自定义内容和交互均已逐项验证。Geyser 旧版 `TagCache.java:97` 的标签空指针属于另一项已知问题，官方修复为 [#6325](https://github.com/GeyserMC/Geyser/pull/6325)；旧版协议 860 构建需要回移修复，不能直接替换为不再支持 860 的新构建。

攻击或切换物品时出现的大型冷却提示由 Geyser 提供。可在 `plugins/Geyser-Spigot/config.yml` 的 `gameplay` 下将 `show-cooldown` 设为 `disabled`，或设为 `actionbar` 移到快捷栏上方，保存并重启 Geyser 后重新进服。黑色文字背景可在客户端「设置 → 无障碍 → 文字背景不透明度」调为 0；这些选项只影响显示，不改变 Java 后端的攻击冷却。

## 配置与数据

程序首次运行会在数据目录生成配置。Windows 双击程序时默认使用可执行文件所在目录；可用 `-data-dir` 指定独立目录。示例见 [`config.example.json`](../config.example.json)。

| 配置项 | 用途 |
| --- | --- |
| `auth_server` | FGAuth HTTPS 验证服务器；本机测试允许 HTTP |
| `servers` / `room_servers` | 国际服列表（名称与 IP:UDP 端口，数量不限）和每个网易账号绑定的国际服序号；`-1` 表示未绑定，不会启动房间。旧配置缺省时仍绑定第一个国际服；默认一个 `127.0.0.1:19132` |
| `upstream` | 与第一个国际服地址保持一致，供旧版本读取；旧配置只有此项时自动迁移为一个国际服 |
| `room_settings` | 每个房间账号独立的房间参数，按令牌顺序保存；包含下列房间名称、密码、版本、人数、公开性、权限、等级、标签、PvP 和自动同意好友选项。旧配置中的同名顶层字段作为迁移和新增账号的默认值 |
| `room_name` / `room_password` | 房间名称（只能是控制台下拉菜单中的内置标题）与密码（6 位数字或留空；旧版本的其他格式密码会被清除） |
| `room_game_version` | 网易房间内核版本，当前适配 `1.21.120.0` |
| `max_players` | 房间总人数，2–30，默认 10，包含房主机器人；普通账号 10 人，不灭钻石 20 人，下界领主 30 人，实际以开房账号权益为准 |
| `friends_only` | 公开性：`true` 为好友可见，`false` 为所有人 |
| `player_permission` | 玩家默认权限：`0` 访客、`1` 成员（默认）、`2` 管理员；实际权限以所进入国际服的设置为准 |
| `min_level` | 准入等级，0–50，默认 0 |
| `room_tags` | 存档标签，最多 2 个：`0` 生存、`1` 创造、`2` 冒险、`3` 模拟、`4` 动作、`5` 建筑、`6` 对抗、`7` 休闲 |
| `allow_pvp` | 允许 PvP |
| `auto_accept_friends` | 自动同意机器人账号收到的好友申请，默认 `true` |
| `forward_resource_packs` | 后端材质下发默认启用；旧配置中的 `false` 自动迁移为 `true`，网页无需设置 |
| `netease_resource_packs` | 兼容自定义预加载配置的 JSON 参数，默认 `false`；文件缺失时回退经典材质，网页不显示此项，见[资源包说明](resource-packs.md) |
| `web_port` | Web 控制台端口，默认 18321，监听所有 IPv4 网卡 |
| `retry_seconds` | 掉线重试间隔，5–300 秒 |
| `debug` | 详细诊断日志，默认 `false`；控制台可在开房期间即时切换 |
| `check_updates` | 自动检查 GitHub 最新版本，默认 `true`；关闭后仍可在控制台手动检查 |

令牌独立保存为 `secrets.dat`，不会写入 `config.json`。Windows 使用当前用户 DPAPI 加密；Linux/macOS 使用文件权限保护，不提供文件内容加密。跨系统迁移时请在新环境重新填写令牌。

控制台的主要页面为「概览、国际服、网易账号、桥接、运行日志」，手机端同样通过侧边栏切换。

- 「概览」展开各国际服的子标签，每次查看一个国际服。电脑上房间在左、国际服在右；手机上国际服在上、房间向下排列，每行两张。虚线箭头指向国际服。点击房间号可复制，旁边的齿轮打开该房间设置，点击头像和昵称进入好友页。「启动房间／停止房间」为同一个按钮，只控制当前国际服绑定的房间。
- 「国际服」以单列卡片展示服务器，绿点表示在线、黄点表示离线。列表下方的「添加国际服」打开名称与 Bedrock 地址弹窗，添加后直接保存；「编辑」同样通过弹窗修改。只有正在运行的国际服不能编辑；移除前需要先解绑其账号，并至少保留一个国际服。
- 「网易账号」添加 FGAuth Token 后显示游戏昵称和正方形头像，可进入好友页。正在开房的账号不能移除，其他账号不受影响。国际服与账号的移除均使用页面内确认弹窗。
- 「桥接」按国际服展示折叠卡片，只列出已绑定账号。点击「绑定」打开账号菜单：已绑定为黄色，未绑定为绿色。绑定、切换和解绑后自动保存，运行中也可修改；绑定到已启动的国际服会启动该账号的房间，解绑只停止该账号的房间。切换到尚未启动的国际服时先保存绑定，再在概览启动。解绑最后一个账号后，该国际服恢复为已停止。保存失败或账号已被其他进程占用时保留原绑定。每个账号最多绑定一个国际服；新账号初始未绑定，不会开房。

各账号的房间设置独立保存，正在运行的房间需要先停止再修改。程序正常启动后不会自动开房，旧配置的 `auto_start` 不再生效；请在概览手动启动。程序内更新完成后的重启仍只恢复更新前正在运行的国际服。连接、管理员账号和更新设置位于左下角「设置」。

账号资料通过 FGAuth 的加密 `/api/phoenix/account_profile` 接口读取，只返回令牌对应的游戏 UID、昵称和头像，不额外登录网易，不创建房间。需配套更新 FGAuth；旧验证站仍可保存令牌、绑定和开房，资料页会提示升级，开房后可显示鉴权得到的游戏昵称。读取到的公开资料缓存在数据目录的 `account-profiles.json`，令牌不写入该文件。

机器人默认每 30 秒检查并同意待处理好友申请（包括连接前收到的申请）。「网易账号 → 对应账号的好友 → 好友申请」中的「自动同意好友申请」切换后自动保存，仅对当前账号生效。好友会话可独立于房间连接；停止房间后仍可在好友页管理好友。成功同意会写入普通日志；失败后独立退避重试，不会导致房间重建，也不会主动向玩家发送申请。

### 好友与私信

在「网易账号」中点击某个账号的「好友」，显示该账号的好友昵称和头像，支持搜索昵称或 UID。点击列表右上角「好友申请」查看待处理申请并手动同意；头像缺失或加载失败时显示昵称首字。打开好友页即可连接对应账号，无需启动房间；即使关闭自动同意，也能手动处理。自动与手动操作共用去重记录。自动同意时，单条失败不会阻塞后续玩家；失败申请继续重试，每轮最多处理 20 条，每次提交间隔 1 秒。查询列表失败时独立退避重试。

点击好友打开私信会话，输入 1–500 字文本即可发送到网易启动器的好友聊天，无需手动填写 UID，也无需启动房间。私信仅支持发送，不接收或同步对方消息。首次发送时才建立聊天连接。发送记录和草稿仅保留在本页，每个好友最近显示 50 条、最多保留 20 个会话，刷新页面后清空。手机上点击会话左上角返回好友列表；支持 Ctrl / ⌘ + Enter 发送。建议配套 FGAuth v1.1.7 或更新版本（`https://github.com/UCKETX/FGAuth`），由验证服提供加密鉴权响应中的 `friend_chat` 凭据。旧验证站仍可管理好友，页面会提示私信不可用。聊天凭据只保留在内存中，不写入配置或运行日志。提交成功表示已交给聊天连接，不代表对方已收到或已读；连接失败时不会自动重发私信。

「运行日志」按国际服切换，不再提供总日志和单房间筛选；同服日志保留 `[房间 N]` 前缀。房间停止后仍可查看本次进程保留的记录，历史记录按产生时所属的国际服归类。移除或替换账号后，内存中的旧房间日志会清除，以免按新账号序号误归类；磁盘完整日志保留。运行日志位于数据目录的 `logs/keeper.log`，状态快照为 `logs/status.json`。分享日志前请检查账号、玩家信息、地址及其他个人内容。

默认记录开关房间、玩家进出、公开聊天、死亡消息和必要错误。遇到问题时，在「运行日志」旁开启「Debug 模式」，或使用 `./NEMCBridge -debug` 启动；详细日志带 `[DEBUG]` 前缀。网页开关即时生效并保存，无需重新开房；关闭后不再写入详细日志，已有日志会保留。

游戏日志来自桥接连接实际收到的消息，不是 BDS 的完整审计日志。没有网易玩家连接时，无法记录国际版直连玩家的事件；服务端未广播的聊天、进出或死亡消息也无法记录。

## 多个房间

每个网易本地联机房间可按开房账号权益配置容量：普通账号 10 人，不灭钻石 20 人，下界领主 30 人，均包含房主机器人；每个房间可接入的网易玩家数为所设总人数减 1。可为同一国际服绑定多个房间，也可分别绑定到不同 BDS。每个房间使用一个独立的机器人令牌，程序不设房间和国际服数量上限。程序不替账号开通会员，最终可用容量以网易节点接受的账号权益为准。

1. 在 FGAuth 用户中心为每个房间添加一个网易账号，创建机器人令牌时在“网易账号”中分别指定不同的账号。同一网易账号同时开两个房间会互相挤下线；“跟随当前使用的账号”的令牌只适合单房间。
2. 在「网易账号」点击「添加网易账号」，分别粘贴令牌。进入「桥接」，在目标国际服卡片中点击「绑定」选择这些账号，绑定关系会自动保存；各账号的房间参数可分别调整。已保存的令牌不会回显，移除账号时会一起移除其绑定和房间参数。
3. 在概览选择国际服并点击「启动房间」。房间卡片列出房间号、状态和人数，点击房间号即可复制；网易玩家搜索该房间号进入对应国际服。

各房间独立鉴权、开房和重连，一个房间掉线不影响其他房间；任一令牌已有本机会话时不会启动任何房间。日志中的 `[房间 N]` 前缀表示消息来自哪个房间。BDS 的 `max-players` 需要容纳所有房间的网易玩家与国际版直连玩家之和。

命令行可通过 `NEMCBRIDGE_TOKEN` 或 `-import-token` 一次提供多个令牌，以空白或换行分隔，顺序即房间顺序。`-check` 会逐个验证令牌，并在两个房间使用同一网易账号时报错。

## 管理员登录

第一次打开页面时会进入初始化，自行设置管理员用户名（1–32 个字符）和密码（8–72 字节），完成后直接进入控制台。之后用这组账号登录；在「设置 → 管理员账号」中输入当前密码，即可修改用户名或密码，修改密码会让其他设备上的登录失效。程序不会生成或在终端显示密码。密码以 bcrypt 哈希形式保存在数据目录的 `admin.json`，不写入配置或日志。管理密码与 FGAuth 机器人令牌是两项独立凭据。

控制台可从局域网访问，初始化完成前，同一网络中先打开页面的人即可设置账号，请在首次启动后尽快完成设置。

也可以通过 `NEMCBRIDGE_ADMIN_PASSWORD` 环境变量设置密码（8–72 字节），适合无界面部署；环境变量中的密码不会回显。启动时该变量优先于已保存的密码，尚未初始化时用户名为 `admin`；取消变量后仍可使用最后保存的密码。

忘记密码时，先正常退出程序，再保留原数据目录执行：

```sh
./NEMCBridge -data-dir ./data -reset-admin-password
```

Windows 对应 `NEMCBridge.exe -data-dir ./data -reset-admin-password`。重置会清除管理员账号，再次打开控制台时重新初始化；如设置了上述环境变量则直接使用该密码。

登录会话有效期为 12 小时，程序重启后需重新登录。点击「退出登录」会注销当前浏览器会话，不会停止房间。未登录时不能读取状态或调用管理接口；登录请求按客户端 IP 限速。

## 命令行与远程管理

```sh
./NEMCBridge -version
./NEMCBridge -headless -data-dir ./data -web-port 18321
./NEMCBridge -headless -data-dir ./data -run
```

`-headless` 关闭自动打开浏览器；`-run` 在启动后自动开房。也可以通过 `NEMCBRIDGE_TOKEN` 环境变量提供令牌（兼容旧的 `LOBBYKEEPER_TOKEN`，新变量优先），或用 `-import-token` 从标准输入导入。完整参数用 `-help` 查看。

控制台默认监听 `0.0.0.0`（所有 IPv4 网卡），终端会输出本机地址和各可用网卡的局域网访问地址。例如终端显示 `http://192.168.1.20:18321/` 时，同一网络的设备可使用该地址访问。`0.0.0.0` 是监听地址，访问时请使用机器的实际 IP。

控制台需要管理员登录。默认使用 HTTP，登录认证不替代传输加密；请通过防火墙将端口限制在可信网络内。远程服务器可使用 SSH 转发：

```sh
ssh -N -L 18321:127.0.0.1:18321 user@your-server
```

然后在本机打开 [http://127.0.0.1:18321/](http://127.0.0.1:18321/)。使用 SSH 转发时，仍应通过服务器防火墙限制管理端口的直接访问。

Ctrl+C、SIGTERM 或网页的退出功能会正常关闭房间。停止房间不会关闭独立运行的 BDS。

## 升级与校验

### 控制台一键更新

控制台每 6 小时检查一次 GitHub 最新版本（可在「选项」关闭自动检查），也可点击顶栏的版本号手动检查。发现新版本时点击「立即更新」，程序会：

1. 下载当前系统和架构对应的发布包，使用 GitHub 提供的 SHA256 或公开仓库中的校验文件验证，校验不通过则放弃；
2. 试运行新程序确认版本号，再替换可执行文件，旧文件暂存为 `NEMCBridge.old`（Windows 为 `NEMCBridge.exe.old`），新版本启动后自动删除；
3. 关闭房间并以原参数重启；更新前在运行的房间会自动重开，房间号可能变化，控制台需要重新登录。

直连 GitHub 失败时，程序依次通过内置加速镜像 `gh-proxy.org`、`ghfast.top`、`ghproxy.net` 检查和下载；某个来源下载停滞或过慢（20 秒内不足 512 KB）时自动换下一个，运行日志会记录实际使用的镜像。能直连 GitHub API 时，镜像下载的文件以 GitHub 提供的 SHA256 为准校验，否则使用同一来源的 `.sha256` 文件。镜像由第三方运营，介意时请关闭自动检查并手动升级。

更新需要程序所在目录可写。Linux/macOS 下程序原地重启并保持同一进程号，systemd 等服务管理器无需额外配置。无法访问 GitHub 或目录不可写时，请按下面的步骤手动升级。

### 手动升级

1. 从 Release 下载新版本安装包；同名 `.sha256` 文件位于公开仓库对应版本的 `release-metadata/<版本号>/` 目录中（旧版本仍在 Release 附件中）。
2. 校验压缩包，例如 Linux/macOS：`sha256sum -c NEMCBridge_v0.1.3_linux_amd64.tar.gz.sha256`。macOS 也可使用 `shasum -a 256 -c`；Windows 使用 `Get-FileHash` 与校验文件比对。
3. 正常退出旧NEMCBridge，再替换可执行文件；保留自己的数据目录和 BDS 世界。
4. 启动后确认后端状态和新房间号。

## 常见问题

### 提示客户端与房主版本不同

先核对 [兼容版本表](compatibility.md)。网易客户端版本、房间版本及后端游戏协议需要分别匹配；修改服务器 MOTD 无法代替协议适配。

### 房间反复断开

确认同一机器人账号没有被其他程序、设备或客户端重复登录。本机相同用户、相同令牌有会话锁，但不能阻止其他设备或同账号的不同令牌。检查日志中的信令、鉴权及网络错误；自动重连不保证保留原房间号。

### 可以加入房间，但进不了世界

检查 BDS 地址、端口、版本、`online-mode`、压缩和方块 ID 设置。将已脱敏的连接阶段日志及双方完整版本号附在问题报告中。

### 看不到皮肤或资源包内容

程序默认通过内置组件预加载后端资源，经典材质本身不加入实际加载栈；普通贴图和原服整套资源已实测正常，详见[资源包说明](resource-packs.md)。

国际版看不到皮肤时，尝试关闭「仅允许受信任的皮肤」并让双方重新加入。特殊商城、4D 或其他自定义模型不保证兼容。后端材质默认自动加载，使用内置组件预加载（不激活经典材质），无需导入文件或勾选选项。已有自定义预加载配置的用户仍可在 `config.json` 中保留 `netease_resource_packs: true`；改为 `false` 可切回经典材质。

先确认国际版直连可显示普通贴图，再检查网易端。Debug 可看到兼容下载、客户端分片请求和后端资源栈衔接；网易最初的响应 3 可能早于实际下载，不能据此判断成功，必须检查最终贴图。加载失败时先检查后端资源包及其依赖，首次下载较大资源请耐心等待。原生组件预加载上下文仍是当前必要条件，默认由内置经典材质提供。多包、多分片、SHA256 和世界初始化已通过自动测试；行为包、脚本、自定义方块/实体及特殊光影仍需单独适配。安装方法见[资源包说明](resource-packs.md#加载后端自制材质)。
